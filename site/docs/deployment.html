Deployment

Deploying a fund on Robinhood Chain end to end: the token, the contracts, the handover to a multisig, then the app, the indexer and the agent that read them.

Before you start

  • $RECURVE. The watcher registry takes its staking token at deploy, or once later through setStakeToken. Until it has one nobody can stake, so no watcher can rule and the fund runs on the depositors' veto alone. $RECURVE is launched on Pons v2, the Robinhood Chain launchpad: 1B fixed supply, 18 decimals, no mint, no owner.
  • A treasury. A Safe on Robinhood Chain. It receives the performance fee and, after the handover, owns the registry and the agent list.
  • A deployer key holding 0.0004 ETH. The deploy burns about 0.00015; the rest is what Forge wants covered up front. This key alone can ever raise the deposit cap and nothing can replace it, so back it up.
  • An agent key holding 0.0001 ETH to start, and some USDG by the first profitable settle, because the performance fee leaves its wallet. A full trading cycle costs about 0.00003 ETH.
  • Foundry and the protocol repo with submodules.

1. Settings

mainnet.env in the protocol repo holds every public value. The keys never enter the repo: the scripts read deployer.key and agent.address from ~/.config/recurve.

VariableValue
VAULT_ASSETUSDG, 6 decimals: the fund is priced in dollars

Constants the script fixes: min stake 1,000 RECURVE (a stand-in, re-sized under After launch), unstake delay 7 days, veto window 24 hours, threshold 20%, two blocks to stop, 5% fee, a 3% slippage cap.

2. Contracts

./deploy-mainnet.sh               # simulates against mainnet, prints every address, sends nothing
./deploy-mainnet.sh --broadcast   # registry, vault, governor and strategy, wired, in one run
./handover.sh                     # shows what moves to the Safe
./handover.sh --broadcast         # registry owner and agentAdmin to the Safe

The deploy refuses to start on any chain but 4663, without a treasury, or below 0.0004 ETH on the deployer. It then writes addresses/4663.json in the protocol repo and app/src/lib/addresses/4663.json in the website repo. The whole deploy costs about 6.7M gas. The handover needs a little ETH on the agent too, since it signs setAgentAdmin.

Verify the source on Blockscout afterwards:

forge verify-contract <address> <Contract> --chain 4663 --verifier blockscout \
  --verifier-url https://robinhoodchain.blockscout.com/api/

3. Everything that reads them

  1. Site, app and docs. All three read the file the deploy wrote, and npm run deploy in the website repo rebuilds and ships them together. The docs render the address blocks on Contracts, the SDK quickstart and the two skill pages from that file.
  2. Indexer. On its service: CHAIN_ID=4663, VAULTS=main:<vault>:<governor>:Recurve Fund, DEPLOY_BLOCK=<block>, LOG_CHUNK=100000. Check /health/indexer after the first backfill.
  3. Runner. Every variable in its .env.example, with DRY_RUN=true for the first rounds. Its key is the agent, funded with ETH and with USDG for fees. Read the log, then turn the dry run off.

4. After launch

  • raiseDepositCap from the deployer key as the fund grows; it only goes up.
  • addAgent from the agentAdmin for a second key; never setAgentAdmin(0).
  • setParameters from the registry owner to size the minimum stake to the token's market price. Two watchers at the minimum stop any proposal and a block is never slashed, so a cheap minimum makes stalling the fund cheap. Recurve's own fund sets it to about $20 of $RECURVE before staking opens.
  • Watchers stake through the app or the SDK; the registry needs no setup beyond the governor it was wired to. If convictions are ever to happen, the registry owner has to point setGovernor at a key that can call convict — the governor itself cannot.
