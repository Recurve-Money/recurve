Contracts

Five contracts: a vault, a governor and a strategy per fund, a registry and a token. Every address, every deploy parameter.

The set

ContractScopePurpose
RecurveVaultPer fundERC-4626 vault with voting shares and a deposit cap. Holds the idle balance, counts deployed capital, runs the redemption queue. Vaults
RecurveGovernorPer fundProposal lifecycle, the agent set, the performance fee. Governance
PortfolioStrategyV2Per fundFixed-basket swap strategy against Uniswap V3 SwapRouter02. Strategies
WatcherRegistryShared by whatever governors point at itStake, verdicts, slashing. Watchers
$RECURVEOneThe token launched on Pons v2: 1B minted at launch, 18 decimals, no owner, no mint; holders can burn. Watchers stake it

The deploy script creates a new registry on every run. A fund's governor takes its registry as an immutable constructor argument.

Deployment order

The vault and governor reference each other, so one of the two is wired after both exist: the governor takes the vault as a constructor argument, and the vault's governor is set afterwards with setGovernor. No address prediction is involved, which is what lets the sequence be reproduced by hand, one contract at a time. This is script/DeployMainnet.s.sol:

WatcherRegistry registry = new WatcherRegistry(reve, 1_000e18, 7 days, deployer); // reve: the $RECURVE token
RecurveVault vault = new RecurveVault(asset, "Recurve Fund", "rvFUND", depositCap);
RecurveGovernor governor = new RecurveGovernor(
    vault,
    registry,
    agent,      // first agent, and the agentAdmin
    24 hours,   // vetoWindow
    2000,       // vetoThresholdBps
    2,          // watcherBlockThreshold
    500,        // performanceFeeBps
    treasury    // feeRecipient
);

vault.setGovernor(address(governor));
registry.setGovernor(address(governor));

RecurveVault.setGovernor is callable once, only by whoever deployed the vault. Any other caller reverts with OnlyDeployer; a second call, or a zero address, reverts with GovernorAlreadySet. WatcherRegistry.setGovernor is onlyOwner, re-settable any number of times, and emits GovernorUpdated. $RECURVE comes from Pons, first or later through setStakeToken, and the strategy last, in the same script; the full sequence with every variable is under Deployment.

Set it before anyone deposits

Until setGovernor runs the vault has no governor and fundStrategy reverts with OnlyGovernor for everyone. Once it runs the address is permanent. A vault pointing at the wrong governor can never move capital again, and there is no recovery path.

Known limitations

Things the code does today that a reader of the design pages would not guess. None is hidden; all are visible in the source.

  • No cancel. A proposal leaves Pending only by veto or execution. A watcher-blocked one stays Pending forever, because execute's block is a revert that undoes its own state write.
  • The queue reserves nothing. float() is the raw idle balance; a strategy can be funded ahead of a queued exit.
  • Standard withdraw and redeem bypass the queue and revert when the balance is short.
  • returned is self-reported. settle checks it against nothing; it drives the fee and the StrategySettled event, not the vault's balance.
  • Share price is inflated between a strategy's return and settle.
  • Slashing is unreachable as deployed. convict is registry.governor-only and RecurveGovernor never calls it; the registry owner would have to repoint governor to a key that does.
  • castVerdict(id, None) counts as a block and can be repeated, so one active watcher can reach watcherBlockThreshold alone.
  • Verdicts are accepted on any id at any time; the registry does not know what a proposal is.
  • Two identical proposals in one second share an id; the second overwrites the first.
  • Admin foot-guns. setAgentAdmin(0) freezes the agent set; removeAgent can remove the last agent; the registry owner can change minStake and unstakeDelay at any time, and unstake uses the delay current at claim time.
  • Strategy weights are declarative; buy and sell do not read them. quotedOut is the agent's word.
  • No pause, no timelock, no upgrade path on any contract, and no setters for the governor's parameters. The only post-deploy knobs are the vault's deposit cap (up only), the governor's agent set, and the registry owner's setParameters, setGovernor and, once, setStakeToken.
