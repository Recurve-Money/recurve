# Recurve

Capital infrastructure for autonomous funds. This folder is the whole website at
recurvemoney.xyz: the marketing pages live here, and the dApp and the docs are
built into it (`app/`, `docs/`), so one deploy ships all three.

## Stack

Static HTML + one CSS file + a few vanilla JS IIFEs. No framework, no bundler.
The pages' only build step is `python3 build/zh.py`, which regenerates `zh/` from
the English pages (see Chinese mirror below). Caddy serves it with clean URLs
(`../deploy/caddy/Caddyfile`).

## Editing

All styling lives in style.css. Change a token there and it propagates.
Header and footer are inlined per page, so edit every page if you change nav.

After any copy change, regenerate the Chinese mirror:

```sh
python3 build/zh.py
```

New English strings need an entry in the `T` dict in build/zh.py (titles in
`TITLES`, meta descriptions in `META`) or they ship untranslated.

A full-width painting (`.band`) is a 3.4:1 strip. On phones it is cropped to 2:1,
so each one carries `object-position` on its `<img>` saying where its subject
sits; set it when you add or swap a painting.

Motion is one thing per page: the hero's words and painting settle in on load
(style.css, "hero entrance"), and it is off under prefers-reduced-motion.

## No gate

The pre-launch passphrase curtain is gone: gate.js, gate.css and their two
background images are deleted, the three tags that loaded them are out of every
page head, the `noindex` meta is gone and robots.txt allows crawling. The site
is public the moment it is deployed. Nothing references the gate any more, so
there is nothing to switch back on - restoring it would mean writing it again.

## Chain

The pages read no chain at all - every page is network-neutral copy, and no
.html names a network beyond "Robinhood Chain". The one chain read is
api/token.js checking an address on Robinhood Chain mainnet when /admin asks. wallet.js:17-30 holds the one
CHAIN object, now pointing at Robinhood Chain mainnet (chainId 4663), with the
testnet values kept in the comment above it; only /admin loads wallet.js.
Chain reads happen in the dApp in app/, not here.

$RECURVE launches on Pons (the Robinhood Chain launchpad). Its address is
not in the code: it is published at /admin, below.

## Token address (/admin)

`/admin` takes a password, checks an address on chain (name, symbol,
decimals, supply, whether the Pons v2 factory created it) and publishes it.
Every page then shows it: the price pill, /buy (address, stats, chart, "Buy on
Pons" to the token's Pons page) and /token. An address published as a test
carries a red "not $RECURVE - do not buy it" line on /buy and /token. With no
address published the pages say $RECURVE launches soon and leave out the
address, the price and the buy links.

The copy that changes carries `data-when`: `token` or `no-token` follow the
published address, a test one included, so a test shows launch day as it will
look; `staking` or `no-staking` follow whether the fund has its token attached.
These elements start hidden and `token-stats.js` shows the right ones once
`/api/token` has answered, so a page makes neither claim while the server is
down. Nothing needs editing on launch day.

Nothing to set up: `npm run deploy` copies the password to the server the first
time, from `~/.config/recurve/admin-password`, and `scripts/serve-site.mjs` keeps
the address in a file there. It speaks Upstash's REST protocol, which is why
`api/token.js` reads like a Redis client. Visitors see a change within about 30
seconds.

Wrong passwords: five tries per IP per 15 minutes, twenty failures in all per
hour, counted before the password is compared. A lockout ends on its own. The
twenty do not hold back an address the right password has come from in the last
thirty days, so nobody can shut the owner out by guessing wrong on purpose.

Locally, `npm run dev` (scripts/serve-site.mjs) runs the same function
against a store kept in `.dev/site-kv.json` at the repository root, with the
password from `ADMIN_PASSWORD` or `~/.config/recurve/admin-password`.
`node --test scripts/serve-site.test.mjs` covers the function.

## Launch (/admin)

`launch.js` deploys the fund from the connected wallet: registry, vault, governor,
strategy, then it hands the agent list and the registry to the Safe. Each step
reads the chain to see whether it already happened, and the draft lives in the
store, so Continue resumes from any browser. `api/token.js` checks the result on
chain before publishing it, and the public read then carries it, which is what
the app goes live from. A published deployment is write-once: only someone with
access to the server can remove it, from the store file.

$RECURVE can come last. Without a real token published the registry is deployed
with no stake token and stays with the wallet; Attach $RECURVE later calls
`setStakeToken`, once, and hands the registry to the Safe. After that /admin
refuses to publish any other token. `deploy/README.md` has the order of things.
